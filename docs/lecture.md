# 進行メモ：動画からハンズオンへ

主催者向けのメモです。冒頭では[Gitのアニメーション](what-is-git-branch-150sec.html)を見てから、今回の課題に必要な点だけを補足します。
ブランチやローカルとリモートの仕組みを、もう一度講義する必要はありません。

## 0〜1分：今日のゴールを伝える

「自分のブランチでページを編集し、PRを作って、CIが成功したら完了です」と伝えます。
動画にはマージや`git pull`も出てきますが、今日はPRのマージまで進めません。
Dockerとコンフリクト解消も必須課題には含めません。

## 1〜6分：アニメーションを見る

主催者のパソコンでHTMLファイルをブラウザで開き、画面に映します。
GitHubのファイル画面ではHTMLのコードが表示されるため、ブラウザで動かすにはファイルをダウンロードして開いてください。
画面共有で見せる場合も同じです。

アニメーションは約2分半です。
通して再生するなら「シーンの終わりで止める」のチェックを外します。
途中で止めて話したい場合は、チェックを入れたまま再生ボタンで次のシーンへ進めます。

前半でブランチとコミット、後半でローカル・リモート、push、PR、マージ、pullが出てきます。
まずは「手元のコミットはpushするまでGitHubに届かない」ことをつかんでもらえれば十分です。

## 6〜8分：動画の例と今回の課題を結び付ける

動画のマージ場面では、`feature`と`main`が同じ場所に行を追加しています。
画面では自動で合流しますが、この例を実際のGitでマージするとコンフリクトになります。
動画はブランチが合流するイメージとして見てください。
今回はコンフリクト解消を操作しません。

動画では最後にマージして`pull`します。
今回のハンズオンはその前で止まり、GitHubにPRを作ってCIの結果を確認します。
PRは取り込みの提案、CIは提出内容の自動チェックです。
「PRを作ったら`main`が変わるわけではない」と一言添えてください。

## 8〜10分：動画にない操作を補い、作業を始める

動画はコミットの前にあるステージ操作を詳しく扱いません。
今回の手順では、`index.html`を保存した後に`git add index.html`で次のコミットに入れる変更を選びます。
`git commit`で手元に記録し、`git push`でGitHubへ送ります。

参加者に「コミット直後、GitHubにも変更がありますか」と聞いてみてください。
答えは「pushするまでは手元だけ」です。
ここまで確認できたら、[READMEの手順](../README.md#1-リポジトリを手元に用意する)へ進みます。

Gitの設定や書き込み権限で止まった人には[準備ガイド](setup.md)を案内します。
エラーが出たら、文面を省略せず画面ごと見せてもらってください。
操作中に状態が分からなくなった場合は、[図解と用語説明](concepts.md)を開いて確認できます。
