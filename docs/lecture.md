# 冒頭10分の説明メモ

主催者向けの進行メモです。Gitを初めて使う人も、PRに慣れている人も同じ必須課題に取り組みます。概念の説明を短くして、作業中に[図解と用語説明](concepts.md)を参照できるようにします。

## 0〜2分：今日のゴール

「自分の変更をPRで提案し、CIが成功したら完了」と伝えます。今日はマージしません。Docker、React、コンフリクト解消は必須課題に含めません。早く終わった人は[追加課題](advanced-git.md)に進みます。

## 2〜6分：手元からGitHubまで

[図解](concepts.md)を見せ、左が手元、右がGitHubだと確認します。手元で編集し、ステージに載せ、コミットを記録してからpushします。pushでGitHub上の自分のブランチへコミットが届きます。PRはそのブランチから`main`への変更提案です。PRを作っても`main`はまだ変わりません。

全員が同じ`index.html`を編集するため、`main`から各自のブランチを作ります。ローカルのブランチとGitHub上の同名ブランチは別々に存在し、pushでコミットを送る点を強調します。

## 6〜8分：短いデモ

`index.html`を1行変えて、`git status --short`の` M`と、`git diff -- index.html`の差分を見せます。`git add index.html`の後に`git status --short`の`M `を見せ、左側の文字がステージの状態だと説明します。差分の読み方は`-`が前、`+`が後です。デモの変更を参加者の提出ブランチに混ぜないようにします。

## 8〜10分：作業開始前の確認

GitとGitHubアカウント、このリポジトリへの書き込み権限、エディタ、ブラウザを確認します。困った人にはその画面を見せてもらいます。WindowsのGit Bash、WSL、Macの手順は[準備ガイド](setup.md)にあります。参加者は[READMEの手順](../README.md#今日の進め方)から始めます。
