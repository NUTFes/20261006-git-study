# 冒頭10分の説明メモ

## 0–2分：今日のゴール

「自分の変更を GitHub に PR として提案し、CI が成功したら完了」と伝える。今日はマージしない。Docker、React、難しい Git コマンドも扱わない。

## 2–6分：手元から GitHub まで

```text
手元のファイル → 差分を確認 → commit（履歴に記録）
                                  ↓
                            push（GitHubへ送る）
                                  ↓
                         PR（変更を提案する）
                                  ↓
                         CI（自動チェック）
```

全員が同じ `index.html` を変更するため、`main` から各自のブランチを作る。ブランチは作業を分ける場所。PR は変更を見せる場所。レビュー承認はマージする時に必要だが、今日の完了条件は CI 成功まで。

## 6–8分：デモ

`git status --short` で変更を見て、`git diff -- index.html` で変更箇所を読むところだけ実演する。コマンドを丸暗記してもらうより、いま何を確認しているかを説明する。

## 8–10分：作業開始前の確認

Git と GitHub アカウント、このリポジトリへの書き込み権限、エディタ、ブラウザを確認する。困った人には対面で声をかけてもらう。Windows Git Bash、WSL、Mac の手順は [準備ガイド](setup.md) にある。
