# 冒頭10分の説明メモ

主催者向けの進行メモです。[README](../README.md)は参加者が操作する教材、[図解と用語説明](concepts.md)は作業中に参照する資料です。この10分ではコマンドの暗記を求めず、Gitが何を記録し、その記録がどこへ移るかを確認します。動画のように`git init`から始める説明も有用ですが、今回は既存リポジトリをcloneするため実演しません。

## 0〜2分：Gitを使う理由を話す

「同じファイルを何度も直すと、いつ何を変えたか分からなくなります。Gitは、その時点の変更をコミットとして記録できます。GitHubは、その履歴をチームと共有してPRを作る場所です」と説明します。[図解](concepts.md#gitは何のために使うのか)の冒頭を示し、GitとGitHubの役割を分けて話してください。

続けて今日の完了条件を示します。「自分のブランチでページを編集し、PRを作り、CIが成功したら完了です。レビュー承認とマージは今日の条件に含めません」。Dockerとコンフリクト解消も必須課題に含めません。早く終わった人は[追加課題](advanced-git.md)へ進みます。

## 2〜5分：変更の置き場所を指で追う

[ローカルとリモートの図](concepts.md#全体の流れ)を画面に映し、次の順に指し示します。

1. エディタで保存した`index.html`は、まず手元の作業ファイルにあります。
2. `git add`で次のコミットに入れる変更をステージに選びます。
3. `git commit`で手元の履歴に記録します。
4. `git push`でGitHub上の自分のブランチへ送ります。
5. PRで`main`への取り込みを提案します。PRを作るだけでは`main`は変わりません。

「保存、コミット、pushはそれぞれ別の段階です」と一度言葉にします。参加者に「コミット直後、GitHubには変更がありますか」と聞き、答えが「pushするまではない」か確認してください。

## 5〜8分：ブランチと差分を短く実演する

主催者のデモ用コピーで`git branch --show-current`を見せ、自分がいるブランチを確認します。`git switch -c`はブランチを作って切り替える操作だと説明してください。全員が同じ`index.html`を編集しても、自分のブランチにコミットするので`main`へすぐには入りません。

デモ用の`index.html`を1行だけ変更し、`git status --short`の出力を比べます。左側はステージ、右側は作業ファイルの状態です。編集直後は次の表示です。

```text
 M index.html
```

`git add index.html`の後は、左側に`M`が移ります。

```text
M  index.html
```

`M`の前後にある空白も意味を持つため、プロジェクターでは`git status`の通常表示を併せて見せると分かりやすくなります。`git diff -- index.html`の`-`と`+`で変更前後を読み、`git add`後は`git diff --staged -- index.html`で同じ変更を確認します。デモの変更を参加者の提出ブランチへ混ぜないでください。

## 8〜10分：提出の流れを確認して開始する

「手元のコミットをpushしても、PRは自動で作られません。GitHubの画面で`main`へのPRを作り、スクリーンショットを添付します」と伝えます。PRは提案、CIは自動チェック、マージは取り込みという順番です。エラーが出たら同じブランチで修正してpushすれば、既存のPRが更新されます。

最後にGit、GitHubへのログイン、リポジトリへの書き込み権限、エディタ、ブラウザを確認します。WindowsのGit Bash、WSL、Macの準備は[準備ガイド](setup.md)にあります。参加者は[READMEの手順](../README.md#1-リポジトリを手元に用意する)から始めます。画面に出たエラーは省略せず見せてもらってください。

## 当日の質問で補うこと

- 「`git add`したのに`git diff`が空です」：ステージ前の差分がなくなったためです。`git diff --staged`を見ます。
- 「pushしたのに`main`が変わりません」：push先は自分のブランチです。PRを作っても、マージまでは`main`へ入りません。
- 「`git pull`でPRを作りますか」：`git pull`はリモートの変更を手元へ取り込むコマンドです。PRはGitHub上で作ります。

最初の10分で説明しきれない用語は、[図解と用語説明](concepts.md)を参照してもらいます。
