# 図で見るGitとGitHub

このページは、手元で編集したファイルがGitHubのPRに届くまでを説明します。コマンドを実行するときに、今どこに変更があるのか迷ったら見返してください。

![手元のファイルをコミットし、自分のブランチへpushして、mainに向けたPRを作る流れ](images/git-local-remote.png)

図の左が自分のパソコン（ローカル）、右がGitHub（リモート）です。GitHubで自分のブランチを作っても、パソコンのファイルは自動では更新されません。同様に、手元でコミットしても、pushするまではGitHubにそのコミットはありません。図のPRは「自分のブランチの変更をmainへ取り込んでほしい」という提案です。PRを作るだけではmainに変更は入りません。

## リポジトリとブランチ

リポジトリは、ファイルと変更履歴をまとめて管理する場所です。この勉強会では、GitHub上のリポジトリを`git clone`で手元にコピーします。手元とGitHubには、それぞれリポジトリがあります。

ブランチは、ある時点の履歴から分かれて続く作業の系列です。ブランチを作ると、共有の`main`を直接変更せずに作業できます。今回は各自が`workshop/<GitHub ID>`という名前で作ります。ブランチは別のフォルダを毎回作る機能ではありません。`git switch`で今作業するブランチを切り替えます。

`git branch --show-current`で表示されるのが、今手元で選んでいるブランチです。`git push -u origin workshop/<GitHub ID>`を実行すると、GitHubにも同じ名前のブランチが作られ、手元のコミットが送られます。`origin`はGitHub上の取得元を指す名前です。`main`は共有の基準ブランチです。

## 編集、ステージ、コミット、push

たとえば`index.html`を保存した直後、その変更は手元のファイルにあります。`git status --short`の` M index.html`は、そのファイルが変更され、まだステージに載っていないことを示します。

`git add index.html`で、次のコミットに含める変更をステージに載せます。この時点の表示は`M  index.html`です。`git commit`で、ステージに載せた内容を手元の履歴に記録します。最後に`git push`でコミットをGitHubの自分のブランチへ送ります。

`git diff -- index.html`はステージに載せる前の差分を表示します。ステージに載せた後の差分は`git diff --staged -- index.html`で確認できます。`git status`と`git diff`は変更を確認するためのコマンドで、実行してもファイルは書き換わりません。

## PRとCI

PRでは、GitHub上の自分のブランチから`main`への変更を提案します。この課題のCIは、HTMLの3か所とPR本文の入力を自動で確認します。CIが失敗しても、同じブランチで修正してコミットし、もう一度pushすれば、元のPRに修正が追加されます。CIが成功しても、PRのマージは別の操作です。
